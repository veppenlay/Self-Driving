# 网络侧鲁棒性实验指导（贴合 epaicar 板端）

本文档沉淀自调研报告、锁存方案与板端约束对齐讨论。

完整消融、细分子集评测台、归因分析放到**确认期**补齐，不挡探索。

## 0. 各实验强制数据边界（必须遵守）

```text
训练集 / 验证集：dataset/26合并
  - train ← train_clean.txt
  - val   ← val_clean.txt

独立测试集：dataset/25地下室
  - test  ← test_clean.txt（指向地下室；只测不调参）
```

| 角色 | 数据集 | 是否可进损失/选模 | 是否可调参 |
|---|---|---|---|
| train | `26合并` | 是 | 是（超参只在此域调） |
| val | `26合并` | 只监控 / 存 best / 早停 | 可看，不把地下室混入 |
| test | `25地下室` | **否** | **禁止** |

**硬规定：**

1. 任何探索/确认枪都必须用上述划分报告结果；禁止把 `25地下室` 并入训练或用其调参。  
2. 禁止再造「只在 `26合并` 内 scan 划分出的伪 test」来冒充正式测试（Codex 旧 ROI 笔记中 `test=569` 即此类，**不算正式基线**）。  
3. 正式对照指标：**地下室 RAW + 固定锁存 HMM MAE**。  
4. 远端标签沿用 `locked_model/labels/remote/labels_2d.csv`（或等价 `current` 路径映射），不得改写 split 语义。

## 1. 策略原则（先读）

| 原则 | 含义 |
|---|---|
| 以胜负为先 | 唯一硬门槛：`25地下室` + 固定锁存 HMM → `HMM MAE < 0.167248` |
| 数据边界不动 | **`26合并`=训练/验证；`25地下室`=独立测试**；锁存权重/HMM JSON 只读 |
| 探索不等于消融 | 探索期允许「高相关改动打包」试一次；**只有打赢再拆解归因** |
| 少做前置工程 | 不上完整 OOD 平台、不先做 A1/A2/A3 全因子、不先啃流式导出 |
| 失败要快 | 单次训练用现有 early-stop；打不过立刻换下一枪，不磨超参 |
| TRT 后置 | 探索期用 PyTorch + 现有评测闭环；**仅对打赢基线的模型**再验 ONNX/TRT |

一句话：

> **在 `26合并` 上训练，在 `25地下室` 上打分；用最少次数、高预期的挑战枪撞开地下室门槛，撞开后再补消融与扰动台。**

## 2. 锁存基线（对照点）

```text
Seq-CfC Temporal3 2D
  + HSV / 底部 70% ROI / 144×192 / 连续 3 帧
  + steering-only HMM online
```

| 项 | 固定值 |
|---|---|
| 网络输出 | `[steering, e_y]` |
| 部署控制 | 只用 `steering`；`e_y` 仅训练辅助 |
| 训练/验证 | **`dataset/26合并`（强制）** |
| 独立测试 | **`dataset/25地下室`（强制，禁止调参）** |
| HMM | `epaicar_deploy/steering_only_hmm_online_model.json` |
| RAW / HMM MAE | `0.204611` / `0.167248`（ve GPU 复核，见 `mp_cursor/baseline_ve/`） |

板端约束（确认期再卡死）：ONNX→TRT FP16、CUDA 10.2、约 30 Hz；产物放 `mp_cursor/exp_*/`，不覆盖锁存 ckpt。

## 3. 两阶段路线

```text
探索期（现在）          确认期（打赢之后）
  快速挑战枪数次    →    消融归因 + OOD/扰动台 + TRT 落地
  只看地下室 HMM        再问“是谁贡献的 / 坏在哪”
```

### 3.1 探索期：推荐射击顺序（按「期望收益 / 工期」）

不做完整消融表。优先单枪或「可部署兼容的打包枪」：

| 顺序 | 代号 | 内容（一次改到位，不拆） | 为何优先 | 工期感 |
|---|---|---|---|---|
| **第 1 枪** | **D1** | 输入追加帧差通道（V 或灰度 `t-(t-1)`），结构其余照锁存 | 与单目 steering 文献最贴；改动面在数据/通道，不碰 loss 协议 | 短 |
| **第 2 枪** | **B0** | steering 高斯 NLL：旁路/`log_σ²` 仅训练，**导出仍 `[steering,e_y]`** | 几乎不改部署形状；可能稳住训练与难例 | 短 |
| **第 3 枪** | **A2** | 仅在 temporal 投影/CfC 段加 LN（**先不要 GN**） | 避开旧 TRT 上 GN 风险；小改归一化 | 短 |
| **第 4 枪** | **S-pack** | 若 1–3 均未破线：把当时最不伤分的 2 项打包再训一枪（典型：`D1+B0` 或 `D1+A2`） | 探索期允许打包求信号；确认期再拆 | 中 |
| **第 5 枪** | **F-lite** | 仅当上面都失败：轻量结构伪标签辅助（车道/可行驶，一条头 + 固定或简单动态权重） | 天花板更高，但要伪标签工期 | 长 |

**探索期明确后置（不要先做）：**

| 后置项 | 原因 |
|---|---|
| 完整 OOD/扰动评测台（原 C） | 不产生新模型；延后「是否有效」的信号 |
| BN→GN 全套 / A1–A3 因子消融 | TRT 算子风险大，且拆因子费时间 |
| 喂 HMM 的在线置信调制 | 先证明 NLL/`σ` 与误差相关；确认期再接 HMM |
| 流式特征缓存 E | 主要省算力，不是最快开准精度红利 |
| 重型光流、SE/CBAM 堆叠、蒸馏/INT8、轨迹/BEV/大模型 | 与任务或板端不对齐，或有失败先例 |

### 3.2 确认期（任一挑战枪 `HMM MAE < 0.167248` 之后）

按需补齐即可，不必一次做完：

1. **拆包消融**：若用了 S-pack，拆成单改动对照，确认主贡献项。  
2. **轻量坏例检查**（迷你 C，半天级）：低光 / 模糊 / 丢帧各 1 档，不必先上完整 Bench。  
3. **部署闭环**：ONNX → Jetson FP16 engine → 与 PT 对齐 → 全栈帧率。  
4. **若做了 B0**：再评估 `σ` 是否进 HMM/EMA；未校准前禁止用 `σ` 覆盖控制。  
5. **需要更多余量时再上 E/F 深化**。

## 4. 每枪操作规范（探索期极简）

### 4.1 必做三步

1. **训练**：`locked_model/train.py`（或同协议的 challenger 脚本），`output-dir` 指向 `mp_cursor/exp_<枪号>_<名>/`；数据必须是 **`26合并` train/val**。  
2. **评测**：现有 `evaluate.py`（`--split test` → **`25地下室`**）+ `apply_current_hmm_postprocess.py`（锁存 HMM JSON）。  
3. **记一笔**：在该目录写 `verdict.md`：

```text
数据：train/val=26合并；test=25地下室
HMM MAE = ?
相对锁存 Δ = ?
结论：晋级 / 淘汰
下一枪：…
```

### 4.2 判定规则

| 结果 | 动作 |
|---|---|
| HMM MAE `< 0.167248` | **冻结该权重为候选**，进入确认期；暂停再堆花样 |
| 接近但未破线（例如 Δ > −0.003 仍劣） | 最多允许 **同一枪改一个显然 bug** 复跑；否则换下一枪 |
| 明显更差 / 仅 val 好看 | 直接淘汰，不调参到地下室 |

### 4.3 接口红线（B 枪澄清）

锁存输出已是 `[steering, e_y]`。

- **禁止**把输出改成 `(steering, log_var)` 或用 `log_var` 替换 `e_y`。  
- 探索期 B0：**额外**学 `log_σ²_steer`，导出/评测主协议仍可保持二维。  
- 确认期若要上三输出或 HMM 置信，再单独开协议变更。

### 4.4 各枪落地要点（够开工即可）

**D1 帧差**

- 在 Temporal3 栈上为相邻帧增加 1–3 个帧差通道（优先灰度或 HSV 的 V）。  
- 同步改 dataset / 导出 shape /（确认期）UDP 预处理。  
- 探索期先保证训练与离线评测一致即可。

**B0 NLL**

- `steering` 用高斯 NLL；`e_y` 仍 weighted SmoothL1。  
- 部署形状保持 `(1,2)` 若裁掉方差头。  
- 不要一开始就改 HMM。

**A2 LN**

- 只动 temporal 投影与 CfC 附近；**先不要全网 BN→GN**。  
- 成功破线后再评估 GN/TRT。

**S-pack**

- 仅当单枪 1–3 均未破线时使用。  
- 只打包「已试过且最不伤分」的项，避免一次上 4 个新旋钮。

**F-lite**

- 伪标签 + 一个辅助头；部署时裁头。  
- 探索期用固定权重即可；动态加权放到确认期。

## 5. 明确不做清单（探索期）

| 项 | 原因 |
|---|---|
| 先搭完整 OOD 台再训模型 | 延迟信号 |
| 因子消融矩阵（未打赢前） | 延迟信号 |
| GN 优先于精度胜负 | 易陷入导出坑 |
| 流式 E 优先于精度胜负 | 工期长、目标是效率 |
| 轨迹/BEV/transformer/语言/扩散 | 无标签或算力不对齐 |
| 几何条件适配器 | 同车同相机 |
| 蒸馏/INT8 重开 | 地下室已有失败先例；非当前瓶颈 |
| 单独指望 SE/CBAM | 上限低；已有空间注意力 |

## 7. 与旧「按模块推进」方案的差异

| 旧思路 | 新思路 |
|---|---|
| C → A → B → D → E → F，步步消融 | **D1 → B0 → A2 →（可选 S-pack）→（兜底 F-lite）** |
| 先基建评测台 | 评测台确认期补；探索期只用地下室 HMM |
| 一步一改、严禁打包 | 探索期允许一次打包求信号；打赢再拆 |
| 训练前验全套 TRT | 打赢后再验部署 |
